# ADR-03: Архитектурный стиль

## Статус

Принято.

## Контекст

Проектируемая система — внутренний AI-ассистент для команды Data Science, объединяющий RAG-сервис и LangGraph-агента. Домен единый, команда небольшая, SLA умеренные (`/chat` p95 < 7 сек, `/agent` p95 < 20 сек). Требуется выбрать архитектурный стиль: модульный монолит, микросервисы или event-driven.

## Альтернативы

1. **Модульный монолит** — единое приложение с чёткой модульной структурой, один Docker-контейнер `app` + отдельный контейнер `Qdrant`.
2. **Микросервисы** — отдельные сервисы для RAG, агента, эмбеддинга, LLM-клиента, каждый со своим деплоем.
3. **Event-driven** — сервисы общаются через брокер сообщений (Kafka / RabbitMQ).

## Решение

Выбран **модульный монолит** в едином Docker-контейнере `app` + отдельный контейнер `Qdrant`.

## Обоснование

- **Единый домен:** RAG и агент тесно связаны (агент использует RAG как инструмент).
- **Небольшая команда:** микросервисы потребовали бы выделенного DevOps и усложнили бы разработку.
- **Умеренная нагрузка:** нет необходимости в независимом масштабировании компонентов.
- **Модульная структура** (`app/api`, `app/services`, `app/rag`, `app/agent`, `app/ml`, `app/repositories`) обеспечивает слабую связанность и возможность выделения сервисов в будущем.
- **Qdrant вынесен отдельно** как stateful-компонент с собственным жизненным циклом и персистентностью.
- **Event-driven** не оправдан: нет требований к асинхронной обработке, гарантированной доставке, сложным пайплайнам.

## Последствия

**Положительные:**

- Простой деплой (один контейнер + Qdrant).
- Лёгкая локальная разработка и отладка.
- Единый CI/CD.
- Возможность эволюции к микросервисам при росте нагрузки.

**Отрицательные:**

- Единая точка отказа для `app`.
- Масштабирование только целиком (нельзя масштабировать только RAG).
- Риск «расползания» модулей без дисциплины.

**Митигации:**

- Строгие границы модулей и запрет на циклические зависимости.
- Горизонтальное масштабирование контейнера `app` за reverse-proxy.
- Готовность к выделению `agent` и `rag` в отдельные сервисы при необходимости.
